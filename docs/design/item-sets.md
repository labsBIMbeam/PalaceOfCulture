# Item sets — the 21-day content cadence

How building items reach the game. The catalog (`apps/web/src/builder/catalog.ts`) is the
single source of truth for WHAT exists; this doc governs HOW new items arrive and which
asset standards they follow. Reference inspiration: Pokémon Pokopia's item system
(materials → processing → blocks → special blocks → furniture, Pokémon-style pockets).

## Cadence

- **One set every 21 days** (the lock numerology — same beat as the 21h/21d craft times).
- Set size after launch: **~21 items** per set. Small, finishable, collectible.
- Every catalog entry carries `set: <number>`; `CURRENT_SET` in `catalog.ts` names the
  latest shipped set. Future UI can badge "new this set" and gate unreleased entries.

## Set 1 — "Foundation" (shipped with this branch)

50 items, **color primitives only** (no custom 3D yet — flat-shaded procedural geometry):

- **8 materials** — raw drip: wood, stone, clay, scrap · refined: boards, bricks, glass,
  parts (`fire_bricks` / `melt_glass` / `press_parts` mirror `mill_boards`).
- **17 blocks** in 4 architectural families (stone cream-grey, warm timber, terracotta
  brick, matte-black steel): 4 cubes, 3 slabs, 3 stairs, 2 fences, window, door + steel
  gate, terracotta + slate roof wedges.
- **25 furniture** — the original five, the Tier-1 domestic set, 2 workstations
  (brickworks, salvage press) and the five resource-mood signature pieces (block clock,
  node rack, antenna mast, solar panel, key cabinet — the only places Bitcoin-orange
  #f7931a and ultraviolet #7b5cff appear; blocks stay architectural).
- **Icons**: generated by Codex from `docs/art/ITEM-ICONS-SET-1-PROMPTS.md`, uploaded to
  Blossom, tracked in `docs/art/item-icons-set-1.manifest.json`.

## Set 2+ — the Meshy pipeline

Each future set upgrades a batch of items from color primitive to real 3D and/or adds new
items. One batch per 21 days, generated with Meshy (AI 3D), then flowing through the
existing pipeline:

1. **Generate** — Meshy text/image-to-3D, prompts derived from the same item descriptions
   as the icon prompts (one prompt file per set: `docs/art/ITEM-MODELS-SET-N-PROMPTS.md`).
2. **Stage** — drop raw GLBs in `assets-incoming/` (never into `public/` directly).
3. **Process** — `packages/assets-pipeline`: gltfpack + Draco mesh compression + KTX2
   texture compression, LOD chain, content hash. Budgets per BUILD-BRIEF §3 (mobile 30 FPS
   is a hard budget — primitives stay as the far-LOD/fallback).
4. **Publish** — upload the processed GLB to Blossom (sha256-addressed); record in the
   set's manifest.
5. **Wire** — future `model?: { sha256: string; url: string }` field on `ObjectDef`; the
   renderer prefers the GLB when present and keeps the colored primitive otherwise, so old
   saves and low-end devices never break.

## Asset standards (why Blossom)

Industry-standard web-game asset delivery, mapped to our FOSS/nostr stack:

| Concern | Industry standard | Ours |
|---|---|---|
| Runtime 3D format | Khronos glTF 2.0 / GLB | same (`packages/assets-pipeline`) |
| Mesh compression | Draco | same |
| Texture compression | KTX2 / Basis Universal | same |
| DCC interchange | OpenUSD / FBX (authoring only) | Blender → GLB |
| Delivery | content-addressed CDN packs + hash-verified manifests (Unity Addressables, Unreal pak/chunks) | **Blossom** (BUD-01/02): sha256-addressed blobs over HTTP, nostr-signed uploads — `blossom.bimcvp.com` |
| 2D icons | PNG/WebP atlases | 1024×1024 WebP on Blossom |

Content addressing satisfies the repo invariant "art is static, state is data": an asset
URL IS its hash, so nothing mutable ever hides in art.
